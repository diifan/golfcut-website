# Verified keyword publishing

The controller owns the append-only Semrush CSV, original exports, SHA256 manifest and daily quota cooldown. The consumer verifies each keyword/metric/URL tuple against the original files. Capped exports contain usable complete rows; their acquisition coverage is explicitly incomplete. Never label a capped export a complete domain inventory.

The consumer tries original alternate source URLs for a keyword, preserving published/reserved records. New source requests are bounded to 500 per scheduled import; successful cached facts are reused. Daily preparation resumes incomplete evidence collection and reserves only a complete target batch.

Course references use public, non-executed structured course data from registered 18Birdies pages. Club identity must match the URL; course layouts must have complete, non-duplicated hole mappings. Tee yardages and par are summed from actual hole values. Missing ratings remain missing. Query identity must match the named venue; prices, tee-time availability, reviews and query operators do not qualify for a scorecard page.

Pages are deduplicated by original source intent, contain dated attribution, and never claim course affiliation or live conditions. Preparation snapshots source evidence and its hash alongside each page; release checks the original export hash, snapshot hash, page hash and immutable manifest. No fixture can stage or publish. Bun build, unique titles, canonical URLs and protected-site checks precede staging. The configured 12:30 Asia/Shanghai tick promotes an already prepared full batch. A shortage stays visible and never becomes a fabricated batch.

Runtime source files are versioned in the same isolated worktree commit as each batch. The protected inference worktree is not edited.
